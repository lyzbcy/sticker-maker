# 账号与资源库

账号与资源库把作品、素材和版本放进一个可由 Syncthing 复制的资源库。登录态、设备配置、浏览器数据和工作缓存仍属于当前电脑。资源库保存的是不可变对象和版本清单，另一台电脑收到完整对象后才能 materialize（还原）出可编辑的本地作品目录。

资源库功能位于桌面应用的 **设置 → 账号与资源库**。绑定时填写发布设置中使用的平台登录账号；这里保存的是账号标识和资源版本，不保存密码、Cookie 或浏览器会话。

## 目录边界

只把资源库根目录加入 Syncthing。根目录必须能看到 `library.json`，例如：

```text
/Volumes/Share/sticker-library/
├── library.json
├── objects/                 # 按 SHA-256 内容地址保存的不可变文件
└── accounts/                # 账号、作品和 settings 的版本清单
```

Syncthing 应同步 `library.json`、`objects/` 和 `accounts/`。不要把整个应用数据目录、发布凭据、浏览器目录、Cookie、`device.json` 或本机工作目录加入共享文件夹。Syncthing 的管理文件由 Syncthing 自己维护，不要把它们当成作品内容导入。

绑定、设备和工作目录属于本机：

```text
<目标目录的父目录>/.sticker-maker-workspaces/<device>/<library>/<account>/episodes
<目标目录的父目录>/.sticker-maker-workspaces/<device>/<library>/<account>/settings
```

其中 `<device>` 是当前设备标识，`<library>` 是资源库 ID，`<account>` 是账号 ID。工作缓存和设置投影用于当前电脑读写，不需要 Syncthing 同步。若必须共享资源库的父目录，应在 Syncthing 的忽略规则中排除：

```text
.sticker-maker-workspaces
.sticker-maker-workspaces/**
```

## 第一次设置 Syncthing

首次使用时先在电脑 A 生成一个完整的资源库，再配置 Syncthing。直接在电脑 B 新建一个空的 Syncthing 目录，里面没有 `library.json`，应用无法把它当成已存在的资源库连接。

1. 在电脑 A 打开 **设置 → 账号与资源库**，绑定与发布设置一致的平台登录账号，并确认旧作品归属。
2. 选择 **迁移并使用新位置**，把当前资源迁移到准备共享的目标目录。先生成预览，确认缺失项为零，再执行；迁移完成后确认该目录已经出现 `library.json`、`objects/` 和 `accounts/`。首次迁移建议保持清理关闭。
3. 在两台电脑安装同一代 Syncthing，并分别启动服务。打开两端的 Syncthing 管理页，记录各自的 Device ID；在电脑 A 添加电脑 B，在电脑 B 接受电脑 A。
4. 在电脑 A 的 Syncthing 中把刚才的资源库目录加入共享文件夹，使用一个明确的 folder ID，并分享给电脑 B。通常使用 **Send & Receive**。
5. 在电脑 B 接受这个共享文件夹时，选择电脑 B 自己的本地目录。它不需要和电脑 A 的绝对路径相同：例如 Windows 可以是 `D:\共享\表情库`，macOS 可以是 `/Users/me/Share/sticker-library`。两端只需使用同一个 folder ID，并最终同步出同一份 `library.json`、`objects/` 和 `accounts/`。
6. 等待电脑 B 的 Syncthing 显示文件夹扫描完成、无待接收文件，并确认本地目录存在 `library.json`。在电脑 B 绑定对应的平台登录账号后，选择这个目录，点击 **连接共享资源库**。
7. 两端都检查“库位置”“本机工作缓存”和作品状态。首次连接后，等 Syncthing 完成同步，再在另一台电脑编辑或发布。

如果资源库目录本来就已存在并包含 `library.json`，可以从第 3 步开始。Syncthing 的 folder ID 是共享关系的标识，电脑之间的本地路径可以不同。

Syncthing 的“文件夹已连接”只表示复制通道可用，不代表每个资源对象已经完整。应用仍会检查版本清单和对象哈希，并显示 `待同步`、`冲突` 或警告。

## 连接、备份和迁移

### 长期连接

连接资源库后，应用会在面板挂载期间定期刷新状态。电脑暂时找不到已连接的目录时会显示 **共享库离线**，保留上一次的状态，不会自动创建一个新的空库。检查磁盘挂载、Syncthing 文件夹路径、双方配对状态和文件权限后，再点击 **刷新资源**。

长期使用时，两台电脑可以都保留连接配置，但同一作品尽量由一台电脑编辑和发布。切换前使用 **准备切换电脑**，等待 Syncthing 完成同步，并在新电脑刷新后确认作品和设置状态。

### 备份导出

1. 在“超级导出”选择 **备份导出** 和目标文件夹。
2. 点击 **生成迁移预览**，先查看来源、作品数量、资源数量、缺失项和总大小。
3. 缺失项清零后点击 **执行已确认预览**。备份导出复制到目标位置，但继续使用当前资源库，不会切换读写位置。
4. 可以在另一台电脑通过 **复制导入到当前库** 合并备份。已有的不可变对象会按内容地址复用，不会覆盖来源库。

预览是执行依据。目标目录、导出模式或清理选项改变后，旧预览会失效，必须重新扫描。

### 迁移并使用新位置

迁移用于把当前电脑切换到新的资源库位置：

1. 选择 **迁移并使用新位置**，填写目标文件夹并生成预览。
2. 审阅每个来源路径以及“迁移后清理已确认复制文件”或“只复制，不清理源文件”的范围。清理选项默认关闭。
3. 先执行复制和完整性校验。只有目标资源库激活成功、文件再次通过校验后，应用才会清理被预览记录且没有变化的来源文件。
4. 若部分复制、清理失败或任务被取消，界面会显示已复制、已清理、缺失和错误项，并保留任务供 **继续执行**。修复路径或权限后可以按 `plan_id` 恢复。

如果源目录本身由 Syncthing 同步，清理删除会传播到其他设备。切换前应让新位置完成同步并在新电脑验证；不确定时保持清理关闭。迁移不会删除外部引用的凭据、浏览器数据或未被预览明确纳入的文件。

### 连接与复制导入的区别

- **连接共享资源库**：把当前电脑指向一个长期使用的资源库，之后会持续发现 Syncthing 到达的新版本。
- **复制导入到当前库**：把备份目录或旧版 `episodes/` 目录合并到当前库，来源目录保持不变；导入前会检查账号归属，账号不一致时需要先切换到对应账号。

对包含 `library.json` 的目录，导入走不可变对象合并；对旧版作品目录，应用会先生成预览和可恢复的复制任务。外部封面、横幅、图标等被引用文件会作为明确的导入项检查，缺失时不会报告为完成。

## 作品状态和占位符

资源状态表示本地资源版本的完整程度，和平台的发布状态是两套信息：

| 状态 | 含义 | 可执行操作 |
|---|---|---|
| `available` / 可用 | 版本清单和所有对象都完整 | 可以按本机权限编辑；满足平台文件要求后才可发布 |
| `placeholder` / 占位 | 已知道平台作品和稳定 `work_id`，本机资源尚未到齐 | 可以打开详情查看；没有完整本地资源时不能编辑或上传 |
| `pending` / 待同步 | 版本或对象仍缺失，或 Syncthing 还在传输 | 等待同步并刷新，不能编辑或发布 |
| `conflict` / 冲突 | 同一作品存在多个未合并版本头 | 先处理版本冲突，不能直接编辑或发布 |
| `deleted` / 已删除 | 共享资源库中存在删除版本（tombstone） | 可通过恢复操作创建新的活动版本 |
| `offline` / 离线 | 当前电脑暂时访问不到已连接资源库 | 只保留缓存状态，恢复目录后刷新 |

平台扫描到当前电脑没有本地资源的作品时，应用会创建占位符，而不是把作品当成新作品。资源对象完整到达后，刷新会把占位符还原到本机工作缓存。详情页仍显示平台状态，但编辑和上传按钮分别受 `can_edit`、`can_publish` 约束。

## 版本冲突和设置冲突

资源库不按修改时间挑选“最新版本”，会保留所有版本头。作品冲突页可以：

- **选用此版本**：以选定版本创建合并结果，保留版本历史。
- **另存为草稿**：创建没有平台作品 ID 的新草稿，不覆盖原作品。

共享生图/发布设置也是版本化实体。设置冲突必须先在 **设置版本冲突** 中确认版本；设置不能另存为作品草稿。`待同步`、哈希校验失败、Syncthing 冲突文件和设置诊断会显示在警告区域，处理完后重新刷新。

## 手动交接和提交结果待核对

准备交接时，应用会捕获当前账号的作品和设置到资源库，随后显示本机状态。请按以下顺序操作：

1. 保存当前批次，点击 **准备切换电脑**。
2. 在 Syncthing 中确认共享文件夹无待接收项，并等待另一端完成扫描。
3. 在新电脑连接同一资源库，刷新并检查作品、设置、占位符和冲突数量。
4. 确认无未处理冲突后再继续编辑或发布。

平台提交如果在网络中断或浏览器超时后无法确定结果，会进入 **提交结果待核对**。应用不会自动重试，避免产生重复作品。先在平台后台确认结果，再点击“已确认提交成功”或“已确认未提交”；这只是记录核对结果，不会替你重新提交。

## 本机隐藏、共享删除和恢复

这三种操作的传播范围不同：

- **本机隐藏**：只把 `work_id` 写入当前设备的本地状态。当前电脑的作品列表不再显示它，Syncthing 不会传播这个隐藏标记，其他电脑仍能看到作品。
- **取消隐藏**：在资源库的本机隐藏列表中恢复显示，不会创建共享版本，也不会改变平台作品。
- **共享删除**：在资源库中写入一个不可变的删除版本，并随 Syncthing 传播。其他电脑刷新后会看到“已删除”状态；应用不会立即物理删除对象，版本历史仍可用于恢复。
- **恢复删除作品**：基于可用版本写入新的活动版本，删除标记也会随资源库同步。若作品同时存在版本冲突，应先处理冲突再恢复。

因此，想暂时整理自己电脑的列表时使用“本机隐藏”；想让所有设备看到删除结果时使用“共享删除”；误删后使用“恢复删除作品”。不要通过文件管理器直接删除 `objects/` 或 `accounts/` 中的文件。

## 常见问题

- **显示共享库离线**：确认 Syncthing 挂载路径没有变化，资源库根目录仍包含 `library.json`，再刷新。不要在离线时选择一个新空目录代替原库。
- **作品显示待同步或占位**：在 Syncthing 中等待对象和版本清单全部到达；确认两端没有暂停或忽略 `objects/`、`accounts/`，然后刷新。
- **出现设置版本冲突**：先确认哪台电脑的设置应作为当前版本，再在设置冲突卡片中选择；不要直接复制本机 `prefs.yaml` 覆盖共享版本。
- **迁移后仍有旧文件**：这是安全保护。若源文件在预览后发生变化、目标校验失败、目标仍是当前库或清理权限不足，文件会被保留；重新检查后再执行。
- **需要备份**：Syncthing 是同步工具，不等于独立备份。应定期使用备份导出或文件系统快照，并保留至少一份与两台工作电脑分离的副本。

## 本次验证范围

超级导出按完整资源库预览和复制，包含共享素材、设置及版本历史；迁移清理只处理已登记的原文件和已验证副本，不按“内容相同”扫描删除其他文件。连接新目录后只自动读取当前工作区，避免旧目录残留重新覆盖作品。

已在 macOS 使用临时数据验证迁移、清理、重启和第二设备连接，并检查桌面及窄窗口界面。尚未在两台实体 Windows/macOS 电脑上验证 Syncthing 传输，也未用真实账号提交平台作品。Syncthing 需在各设备单独配置，应用不会自动安装或配对。
