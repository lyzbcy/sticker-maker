## 二、逐条第一性原理分析与解决

### P0 · 表情名称含空格（4/5）—— ✅ 已修

- **第一性原理**：平台规则明文"表情名称应避免出现空格"。系列命名模板
  `f"{series.name} {number}"` 自带空格 → 全系列必被拒，与内容质量无关。
- **解决**：`series.py album_name()` 去空格（`周三涵做表情69`），前端显示同步
  （commit `53da501`）。存量：待审核的 66/67/68 需在平台「编辑」手动改名，
  不必等被拒。

### P1 · 聊天页图标（3/5 明说，波及 4/5）—— ✅ 已修（icon_mode=ai）

- **第一性原理**：平台硬规则"图标 = 只含形象头部的正面图像"。图标在手机上
  是 50px 的小图，只有"大脸+简笔"才可辨认。而管线原图标 = 封面同源（16 张
  完整表情之一缩放）——带动作/道具/特效，**再怎么挑张也挑不出合规图**，
  因为格子里根本不存在"纯头部照"。
- **解决**：图标单独生成（`assets.py make_icon`）：
  - `icon_mode = "ai"`（新默认）：S3 用 codex 以 base 图为参考，单独生成
    "纯头部正面照"（大脸占 80%、无道具无文字、洋红底供抠图）→ chromakey
    抠底 → 50×50。角色 IP 由 base 参考图保证，与 S1 门禁同源。
  - codex 失败/超时 → fallback 原 `_pick_best_face` 选张（保证素材永不缺失）。
  - 用户可在详情页把 `icon_mode` 改回 `pick/custom`。
- **成本**：每单多一次 codex 调用（约 1–2 分钟）。

### P2 · 表情图多余边框线（62）—— ✅ 已修（边缘残留带 trim）

- **第一性原理**：微信贴纸 = 角色本体（含角色描边）。任何"矩形边框线/格线
  残留/非角色底色"都是切割阶段的泄漏。62（旧等分切割 + 生图黑底异常）实锤：
  整圈品红格线 + 黑底保留进成品。现管线（内容感知切图 + chromakey 抠洋红）
  成品四边已透明（66/68 实测），但仍有两个缺口：
  1. 生图不按 prompt 画洋红底时（黑/白底），chromakey 认不出 → 整块底色保留；
  2. `_EXPAND_PX=6` 外扩 + `_ensure_size` 补方时"四角同色不透明"会用残留色补边。
- **解决（双层防御，chromakey 后、补方前）**：
  - **第一层 `remove_edge_background()`**：把"与边缘连通的背景色"抠成透明。
    边缘采样前 2 种不透明主色为背景色，从四边 flood（色距<60 连通即抠）。
    连通性是安全判据——即使角色黑发与黑底同色，也因被白描边包裹、不接触
    边缘而保留；抠除面积 >80% 判异常不动。62 实测：黑底+品红格线全抠净，
    角色完好（视觉对比验证过）。
  - **第二层 `trim_border_band()`**：裁掉四边"≥95% 同色不透明"的薄残留带
    （`_EXPAND_PX=6` 泄漏的格线/补方色），单边最多 25% 防误杀。
  - 两层均为模块级函数，S2 成品与 P1 的 AI 图标共用。

## 三·b、批量重提实战（2026-09-01）

- **编辑器类（63/64/65/66/69）→ 5/5 全部成功**：「修改完毕」流程（管理页→详情→
  编辑→新标签编辑器→按驳回理由精准改→提交）。每单 AI 图标均生成成功。
- **编辑器硬限制（实测）**：已上传的 16 张表情图**完全不可修改**——无删除、
  无单张替换（hover 只有"裁剪"，裁剪对话框无重传入口）、整体重传=**追加**
  （62 实测变 24 张且含义词错位→提交失败不保存，无污染）。
- **结论**：表情图本身有问题的单（62/68 边框线）编辑器救不了 → 本地
  repolish 后走「再次提交」（新建流程）发新单，旧单平台手动删除。
- 待审核中的作品编辑按钮被平台锁定（61 首次提交成功后再想编辑被拒）——
  编辑窗口只在"未通过审核"状态开放。
