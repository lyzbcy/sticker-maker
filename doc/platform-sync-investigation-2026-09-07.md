## 已确认的数据通路

- `GET /cgi-bin/mmemoticon-bin/home?lang=zh_CN&f=json`：本账号一次返回 `List` 303 条，303 个不同 `StikerID`。界面为 31 页，但此次列表响应已包含全量作品。
- 每行字段包括 `StikerID`、`Name`、`Status`、`ModifyTime`、`DownloadNum`、`SendNum`、`Rewards`、`TotalDownloadNum`、`TotalSendNum`、`DataTime` 等。须保留当前界面的统计口径，不能随意混用当日与累计字段。
- `GET /cgi-bin/mmemoticon-bin/stikerpage?stikerid=<作品ID>&f=json`：返回 `StikerID`、`Status`、`Reason` 等。`Reason` 为 JSON 字符串，按素材字段分组，值为理由数组。
- 第 182 单 `Reason.paneliconurl` 有两条图标理由，与驳回页面文本相同；第 180 单有一条图标理由。
- 单次登录态复测：列表 778 ms，第 182 单详情 285 ms，第 180 单详情 284 ms。仅为本机本次请求时间，不代表完整同步耗时或稳定性能承诺。
- 可用平台作品 ID 精确关联与定位，避免名称包含匹配和反复从首页翻页。

这些是网站内部请求，尚未验证其他账号、大于当前数据量的分页行为及版本兼容性。实现需要检查登录失效、业务错误码、结构变化、数据完整性，并保留页面读取降级。

## 审核轮次的证据边界

列表 `ModifyTime` 只有日期，如 `2026-09-07`。`DataTime` 不能未经验证当成审核时间。两份详情响应及已查看页面未发现审核轮次、审核事件 ID 或精确审核时间。

因此不能用“作品 ID + 日期 + 理由文本”保证识别每一次审核：同日重提且再次收到相同理由时会碰撞。作品 ID 是作品身份，不是审核轮次。

建议保存本地提交记录与审核历史：

1. 本工具确认重提成功时记录新提交轮次；失败或结果不确定不得盲目递增，后续先对账。
2. 观测到待审核后再次驳回，可归入对应的新提交轮次；与已有本地提交记录合并，不能双计数。
3. 同轮重复扫描不新增记录；同轮理由内容变化更新本轮内容；新轮即使理由相同也保留新记录。
4. 平台外手动重提且同步错过中间状态，当前证据不足以精确推断轮次，应允许手动标记重提或标注待确认。缓存不能宣称覆盖该情况。
5. 保留完整历史，当前理由独立展示；旧数据导入标记为历史未知轮次，不虚构为真实第一轮。
