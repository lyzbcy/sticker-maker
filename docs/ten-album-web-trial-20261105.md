## 本轮修复与沉淀

1. 第一格构图在首次提示词中约束，头像固定取原第一格顶部居中80%方框；10弹均无头像重生、抠字、轮廓mask或选格识图。横幅与赞赏图调用当前仓库现有引擎逐弹渲染。
2. 624：ChatGPT明确回复“目前这条消息里没有收到附件”。旧发送门禁只看任意发送按钮/全页进度，不能证明对应输入框里有附件。已将附件、文本、按钮绑定同一composer，缩略图数量须等于base数量且上传结束才能发；在原会话补传后成功。保留原sentAt，补救时间独立记recoverySentAt。
3. 增加resume阶段：保留原批次及概率抽样，跳过已审组、已切图和已发送请求；继续读取原会话并推进未发送的弹，不重跑全部、不重置时钟。
4. 626：默认空带中线误检为793，导致2/3列混格。直接整格重切仍有邻格碎片，已否决并保留失败文件。最后调用原引擎显式fixed_grid等分归属，仍按现有连通域完整取图，修复越界碎片。原图未重生；重建源图证明与配套后重新审图、绑定当前SHA。该可选参数默认关闭，未改变桌面默认切图或制作第二套算法。626两次重切约2.784/2.501秒及重建时间均在生产总钟内。
5. 同次回复JSON仅作含义候选，逐组实际核对32格和10配套，未盲信文字映射；全部含义清除标点并保持单弹唯一。
6. 各发布组独立sdk-journal与回执，主partial-receipts逐组落盘，拒绝重放已有提交日志。

概率沿用config.yaml，10次实际抽样为星星布丁5、捞鱼5、双人0，没有为凑概率重抽。
