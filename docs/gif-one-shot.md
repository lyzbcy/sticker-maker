# 一次生图 → 多帧 → 循环 GIF

## 已验证的最小闭环
角色 base + 动作参考 → **一次 image_gen 调用产出一张 4列×2行、8帧动作表** → 本地切帧 → 统一调色板 → 透明 GIF → 全帧解码/视觉检查 → 精选目录。
星星布丁和捞鱼各调用一次生图，各输出一个 240×240、8帧、50ms/帧、无限循环的打拳 GIF。本地裁切、缩放和编码不再调用生图服务。这里记录调用次数，不代替服务商实际额度/计费口径，也不承诺所有动作一次即可合格。

## 可直接复用的提示词模板
```text
角色参考图只约束身份；动作参考只约束动作，不能混用主角。
生成一个严格4列×2行、按行排列的8帧动画动作表，不是8个独立表情。
同一角色、同一相机、同一比例，头顶和脚底位置稳定；四周留足边距。
所有格子保持发型、五官、眼镜/耳饰、服装及材质；真实透明背景。
动作：准备→右拳前伸→右拳最大→右拳回收→准备→左拳前伸→左拳最大→左拳回收。
拳头朝镜头产生透视放大，肩膀轻微倾斜，气鼓鼓但可爱；结尾衔接第一帧。
无文字、格线、水印、其他人物；不能跨格、裁脚、缺手或改变角色身份。
```

## 本地可运行原型
依赖 Python + Pillow；不需要生成服务凭据、不读应用配置、不访问网络。
```powershell
python "E:\共享\创业\01-捞鱼软件产品\sticker-maker\reference\gif-one-shot\assemble_gif.py" "动作表.png" "新成品.gif" --cols 4 --rows 2 --size 240 --duration 50
python -m unittest discover -s "E:\共享\创业\01-捞鱼软件产品\sticker-maker\reference\gif-one-shot" -p "test_*.py" -v
```
- 新文件输出，已存在路径拒绝覆盖；原始大图及角色 base 不改。
- 支持 `--row-cuts` / `--col-cuts` 显式边界，格式为从0到图像宽/高的递增整数列表。
- **生成器不保证数学等分**：捞鱼原图1774×887，水平透明沟在448—450附近，实际使用 `--row-cuts 0,450,887`，避免第一排鞋底误切。需要视觉/透明沟定位，不能盲目等分。
- 使用共同方形画布和共同尺度，不逐帧按前景包围盒独立居中，否则会把出拳位移错误抵消，产生比例闪烁。
- 所有帧共用255色调色板，第255号为透明色；alpha<128转透明，`disposal=2`，`loop=0`；GIF毫秒值按10ms粒度。半透明发丝会量化，原始RGBA动作表必须保留；后续考虑APNG/WebP预览。
- GIF编码器可能合并连续相同帧，验收使用实际解码帧数和时长，而非仅以输入格数推断成功。
- 原型版本在 `assemble_gif.py::__version__` 为0.1.0，与正式应用版本独立。

## 验收与失败状态
1. 技术验收：图像可解码、裁切边界合法、尺寸正确、实际帧数≥2、透明角像素/无拖影、时长/循环、文件SHA、复制一致。
2. 视觉验收：角色身份、眼镜/配饰、动作方向、躯干/脚底稳定、无跨格和截断、拳头无畸形；检查首/中/末及整段循环。技术测试不等于人工审美通过。
3. 保留 sheet、实际prompt、参考图哈希、参数、GIF、验证JSON；失败分别归为生成、切帧、透明、编码、身份或循环错误，不直接整链重试。
4. 准许用户预览并只重做失败阶段；若身份/动作表失败确需重新生图，应明确新增调用，设置预算上限，不能宣传零重试保证。
5. 本轮4个原型单测通过：8帧及透明解码、拒绝覆盖、非法时长、非法边界。没有声称完成生产集成/全量回归/新版本发布。
