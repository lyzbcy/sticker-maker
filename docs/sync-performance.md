## 实测根因
- 只读接口实测返回 605 单，用时 1.204 秒；状态分布 7:167、5:300、4:129、2:7、11:1、8:1。
- `parse_list` 遇到唯一的未知状态 11 就拒绝全表，触发 70 多页的 DOM 降级；不是接口本身必须逐页翻。
- 平台真实首页 JS 已核验：List 的 1 已保存、2 待审核、3 审核中、4 未通过审核、5 审核通过、6 已预约上架、7 已上架、8 已下架、9 强制下架、10 预约上架失败、11 限制投稿；不套用 EmojiList 的另一套枚举。原始片段见 verification/sync-speed-20261013/platform-schema.txt。
- 登录入口先等首页完整 load，已有效的会话也可能卡住；`sync_status` 又新建 LibraryRuntime 冷刷新，丢掉既有缓存。
- 驳回详情已有审核轮次缓存，但所有未缓存详情串行请求；网络取消要等当前请求完成。

## 改动约束与验收
1. 结构/重复身份错误仍拒绝写入；未知状态单独列出并保留本地数据，已知状态继续接口同步。未知状态存在时 list_complete=false，禁止当成全量可信审核结果执行上架。
2. 仅在 BrowserSession 既有账号证明通过后直接读列表；会话失效才走原登录流程，不导出登录信息。
3. 理由只读 GET，最多 3 并发，限流降为单路并退避；逐单落库，失败不覆盖已有理由，审核周期守卫保留。
4. 取消停止排队/在途详情请求；保留已完成结果；显示接口模式、数量、跳过缓存和阶段耗时。
5. 复用 engine 上的资源库 runtime；源数据锁与原有后置资源入库保留。
6. 单测覆盖未知状态隔离、账号证明、缓存命中、部分失败、取消、并发上限；用相同 605 单规模基准和真实只读接口计时验证。

## 用户选项与预计耗时
- “同步驳回理由”默认关闭，CLI `fetch_reasons` 缺省也为 false；上架预检始终只取状态。
- 页面同时显示两种模式的预计耗时，以及已知驳回数/未缓存理由数；仅需要查看、整改驳回理由时勾选，日常状态刷新/一键上架建议不勾选。
- 冷启动按作品数、待补理由数估算区间；完成后按真实墙钟时间和理由阶段耗时更新本机估算。取消/DOM 降级耗时不参与学习。
- 真实平台只读＋隔离元数据实测：605 单状态 7.833 秒；首次 129 单理由 37.987 秒；理由缓存命中后 7.849 秒。本机库全链路另测。
- 平台状态仅提交已验证父修订的元数据，不扫描或哈希素材；保留其他本地字段和图片，同作品双投影只对齐平台字段。真实共享版本变化时保留本地结果并报告待处理，不覆盖远端。
- 本机原有 453 个作品处于素材版本冲突（更新前 device.json 的 last_rows 已证实）。这些作品的平台只读观测保存到账号隔离的本机 platform_observations，不改任何素材 head、不自动合并冲突；界面可显示最新平台状态，投稿/上架的素材冲突门禁不变。
- 状态提交后定向更新现有作品列表快照，避免再扫整库素材；新增作品仍走正常入库和列表刷新。
- 平台同步前仅校验账号绑定和资源库连接，不物化/扫描全部素材；素材编辑、投稿等命令的完整前置检查不变。逐作品共享写入仍检查精确父修订，发生并发版本变化时保留本机结果并提示。
- 仅检查时间变化时保留为本机观测，不创建共享修订；命中理由缓存不再更新审核历史的 last_seen_at。收益汇总是附加读取，导航最多等待 8 秒，失败保留旧收益，不拖住已经完成的作品状态。

API 会话与请求上下文行为参照 https://playwright.dev/python/docs/api/class-apirequestcontext 。
