# 资源库重构与交互修正

## 模块边界
原 ResourceLibraryPanel.vue 的模板、状态、纯展示、IPC、进度和操作流程混在一个组件。候选入口70行，原DOM区块顺序和data-test入口保留：
- LibraryStatus / LibraryAccount：资源状态与账号。
- LibrarySettingsConflicts / LibraryWorkConflicts：设置冲突与作品冲突，仍按原位置展示。
- LibraryTransfer：导出预览、复制/迁移、连接/导入、任务续接。
- LibraryOperations：未知提交结果核对；不自动重试。
- LibraryRecords：本机隐藏、共享删除、恢复，显式标为高级操作。
- LibraryHandoff：切换设备交接。
- state.js：每个面板独立的ref与派生状态，不建立全局单例。
- gateway.js：唯一IPC传输适配，保留JSON复制Vue Proxy的边界。
- actions.js：原业务命令、预览失效、确认与回执处理。
- progress.js：旧/新进度载荷解析与用时计时。
- useResourceLibrary.js：订阅、30秒轮询、冲突延迟刷新及统一卸载清理。
- presenters.js：15个无IPC的展示函数。
- context.js：每个面板只注入自己的model，8个视图不重复启动控制器。
- views.css：只作用于resource-library-view包装区，避免影响原ResourceLocationPanel/ProjectStoragePanel。包装区display:contents，原flex卡片布局保持。

## 已复现并修正的行为
1. 取消选择目标目录不再丢失已有路径和有效预览；选择同一路径也不作无意义失效。
2. 选择目录失败保留已有路径，并在面板错误条显示原因。
3. 共享删除待回执期间单飞，隐藏/恢复/取消隐藏共用recordAction；原显式确认保留。
4. 面板卸载解除自身进度订阅、轮询、用时计时和冲突刷新计时器。
5. 冲突请求在卸载后才返回时，不再创建新的延迟刷新或额外状态查询。
6. 每个面板模型仍相互独立；共享删除被拒绝确认时不发送命令。
