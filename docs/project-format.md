# 规范工程与瘦身（0.6.0 候选）

工程目录本身就是可编辑、可投稿的唯一工作目录。规范工程模式没有 objects/ 素材库，也不会生成 .sticker-maker-workspaces。旧模式在显式转换前继续兼容；升级源码或打开候选程序不会自动迁移或删除真实作品。

## 文件格式

```text
微信表情包/
  projects.json                         集合标识与格式版本
  周三涵做表情37/
    project.json                        工程身份、元数据、含义顺序、文件 SHA/大小、模式
    原图/                               宫格原图和必要无字源图
    参考图/                             工程源素材
    最终版/                             原有文件名与字节保持
    封面/ 横幅/ 图标/ 赞赏图/            已生成的投稿素材
    rating.json                         人工原始分数与备注，保留既有格式
    .cache/                             明确可重建的缓存
  星星布丁第一弹/
  星星布丁第二弹/
  .project-data/
    settings/                           账号设置，直接使用这一份
    records/                            投稿意向、未知结果和必要记录
    history/                            释放旧副本时保留的独有历史字节及映射
```

为兼容现有编辑器、投稿器及用户文件，正式图片目录继续沿用中文名，不要求人工把「最终版」改成 stickers。`project.json` 的 format 为 `sticker-maker-project`、schema_version 为 1，核心字段：

- metadata：稳定 work_id、account_id、专辑名、系列编号、介绍、平台 ID 和审核观测等。
- files：相对路径映射到 sha256、size；不把绝对文件路径作为作品身份。
- meaning_map：数字字符串序号到含义词，保留原有投稿顺序。
- characters、recipe：角色及已记录的制作参数；不承诺 AI 生成逐字节复现。
- mode：full（完整）或 delivery（精简）。
- source_directories：明确分类的源素材目录。
- cleanup_pending：中断清理的校验清单，完成后移除。

旧 meta.json、meaning_map.json、介绍.txt、角色卡会在转换或生产者保存时吸收进工程清单。rating.json 的人工数值和来源记录不做分制转换，不因移动目录改写历史评分内容。评分中的旧路径可作为来源记录保留，工程定位使用 project.json 的身份。

新生成的切分格子在 `.cache/panels`，不纳入正式文件清单；原宫格与无字源图仍保存。旧版 `_panels` 可能含人工改动，不自动视为缓存或删除。

## 命名与发现

目录默认就是专辑名称，不添加设备、账号、资源库哈希或 episodes 层级。特殊文件系统字符用可读字符替代；同名不同工程使用「（副本2）」等后缀，不覆盖。工程改名后更新返回路径，前端跟随新路径；在文件管理器中改名后按 work_id 重新发现。

「周三涵做表情」系列继续使用阿拉伯数字；系列名为「星星布丁」「星星布丁第」「星星布丁系列」时生成「星星布丁第一弹」「星星布丁第十弹」等。旧目录名字不擅自换算。未完成制作暂用「制作中表情」，未命名结果用「未命名表情」，并发时原子分配可读后缀。

## 用户入口

未连接资源或原位置离线时，主页直接显示「选择资源位置」。设置 → 账号与资源库顶部也始终提供该入口。

选择旧资源库、规范工程集合或其上层文件夹后，应用只检查所选目录及直属子目录，列出识别出的资源和账号；选择单个规范工程时查找其所属集合。确认账号归属后连接，不再要求先手工填写账号或合并旧库。连接配置仅保存在当前设备，下一次启动自动加载；切换前的本机配置保存在 resource_library/connections，连接失败恢复原配置。多个账号必须明确选择，取消文件夹选择清除先前候选。

规范工程直接读写原目录，不创建完整工作副本。旧资源库仍使用旧版工作副本机制，连接页会明确说明；停用副本需继续下方的规范工程转换流程。目录发现不执行转换、清理、投稿或预约。

设置 → 账号与资源库 → 转换为规范工程：

1. 选择工程根目录并生成预览。逐文件校验库对象，检查本机投影中未入库的文件和人工评分；真实素材或元数据分歧会阻止执行。
2. 按预览转换并切换。操作意向/未知结果及已删除状态保留，不进行任何真实投稿或预约。
3. 新工程验证可用，其他设备切换或停止使用旧库后，预览释放旧库和工作副本。独有历史字节保留到 history；校验通过才删除旧文件，变化文件保留并报错。
4. 对既有「周三涵做表情N」「星星布丁第N弹」目录，可预览规范旧目录。散放成品移入「最终版」，工程文件补齐；不按名称猜测平台身份，不覆盖另一个同名工程。

转换保留源数据时会暂时增加占用。转换、清理是两个不同阶段；预览不是已释放空间，移动到别处也不等于释放整块磁盘空间。旧副本删除会随 Syncthing 传播。

在作品详情 → 工程瘦身：

- 默认只删除 `.cache` 中的可重建文件。
- 主动勾选删除原图/参考图，预览后确认，转为 delivery。
- 保留最终表情、投稿素材、评分、工程身份和含义顺序；未分类文件和人工来源证据不会被猜测为垃圾删除。
- delivery 可以查看、评分、导出和用现有素材投稿；不能重新裁切、加字或生成素材。恢复这类能力需从完整工程备份还原源素材，当前版不提供 AI 猜补原图。
- delivery 的刷新和重启不补回原图。旧资源库及外部备份的空间需单独处理。
- 有未决投稿、占位/缺失资源、同步冲突、未保存文件变化时，瘦身阻止执行。实际投稿仍走原来的格式、身份与结果核销门禁。

## 同步及写入边界

同一工程优先由一台电脑编辑；完整同步后再换电脑。共享工程本身，登录态、凭据和 device.json 仍在本机。`.project.lock` 是 OS 锁，文件残留不代表仍被锁定；建议在 Syncthing 根忽略规则中排除 `.project.lock`，但不要排除 project.json、正式素材或 `.project-data/records`。

元数据使用原子替换、预期修订号及跨进程工程锁。相同 work_id 的多个目录、相同平台身份的多个作品、Syncthing 冲突文件不会自动选一份覆盖。规范工程模式下，旧版对象库导入/迁移按钮不执行，备份可直接复制完整工程集合。当前没有与旧版客户端双向混用的兼容保证。
