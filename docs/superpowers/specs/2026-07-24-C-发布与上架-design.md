## 0. 定位

### 0.1 职责

把 A 产出的 episode（一弹完整素材）**一键提交到微信表情开放平台**审核，审核通过后**批量预约上架**。是**开发者（捞鱼本人）的工具链**，不进粉丝分发包。

### 0.2 为什么不进粉丝分发包（C1 决策）

现有 publisher skill 绑死你的微信账号（`.env` + `.browser-data`）。发布到微信平台用的是**你本人的创作者账号**——粉丝软件不能、也不该能发布到你的账号。所以 C 是独立 CLI 工具，只在你本机跑。

### 0.3 交付边界

- **交付**：`sticker_engine/publish/` Python 包 + `publish-cli` 命令入口（playwright 自动化）
- **不交付**：不进 B 的 .app 分发包；不需要粉丝装 playwright
- **验证**：mock playwright 单测 + 真实平台手动冒烟（需你的登录态）

## 2. 架构

### 2.1 模块结构

```
sticker_engine/publish/           ← C 新建（不进粉丝 .app 的 PyInstaller）
├── __init__.py
├── cli.py                        ← publish-cli 入口（argparse）
├── publisher.py                  ← Publisher 类：单弹提交（24步迁移）
├── shelf.py                      ← Shelf 类：批量预约上架（7步迁移）
├── batch.py                      ← 批量发布（分批+断点续传+重试）
├── browser.py                    ← BrowserSession：playwright 封装（登录态持久化）
├── config.py                     ← PublishConfig（赞赏图路径、固定配置）
└── selectors.py                  ← 微信平台选择器常量（集中管理，改版易修）
```

### 2.2 与 A 的关系

C **复用 A 的 episode 产物**（`最终版/`、`横幅/`、`封面/`、`图标/`、`介绍.txt`、`本次制作角色.md`），但**不 import A 的核心库**——C 是独立的发布层，只读 episode 目录的文件。这样 C 可以单独打包/运行，不拖累粉丝的 .app。

### 2.3 数据流

```
A 产出 episode 目录
   ↓
publish-cli publish --dir <episode>   ↓（读 episode 素材）
Publisher.publish(episode_dir, config)
   ↓ playwright 自动化
微信表情开放平台（登录→24步表单→提交审核）
   ↓ 审核通过后
publish-cli shelf                     ↓
Shelf.shelve_all()（扫描审核通过→预约今日上架）
```

## 3. Publisher：单弹提交（24 步迁移）

### 3.1 24 步映射（现有 skill → playwright）

| 步 | 现有 skill 动作 | playwright 实现 |
|---|---|---|
| 1 | 打开首页 | `page.goto(HOME_URL)` |
| 2 | 账号密码登录 | 读 .env 填表单 / storage_state 跳过 |
| 3-5 | 提交作品→选专辑→选类型 | click text 选择器 |
| 6 | 上传表情图（按故事线顺序） | `set_input_files`，按 meaning_map 排序 |
| 7 | 填含义词 | `evaluate` 设 value + dispatch input 事件 |
| 8-9 | 名称 + 介绍 | 读 episode name + `介绍.txt` |
| 10 | 版权信息 | 固定"捞鱼真不吃鱼"（config 可改） |
| 11-13 | 横幅/封面/图标 | 优先 episode 的 `横幅/横幅.png` 等 |
| 14-18 | 类型/角色/风格/主题/地区 | 固定配置（config 可改） |
| 19-22 | 接受赞赏 + 引导语 + 两张赞赏图 | config 的赞赏图路径（默认你的） |
| 23 | 提交 | click 提交按钮 |
| 24 | （新增）验证提交成功 | 检查页面文案/URL |

### 3.2 关键改进（vs 现有 skill）

- **storage_state 持久化**：playwright 原生支持，比 puppeteer 的 .browser-data 干净。首次登录后存 `~/Library/Application Support/StickerEngine/publish_storage.json`，之后自动复用
- **含义词上传顺序**：现有 skill 已按 meaning_map 排序（经验沉淀14），C 保留——读 episode 的 `meaning_map.json`，按 key 1→16 排序上传
- **赞赏图缩略图验证**：现有经验12（防假阳性），上传后检查缩略图数量增加；裁剪框自动点确定（经验13）

## 4. Shelf：批量预约上架（7 步迁移）

| 步 | 动作 |
|---|---|
| 1 | 打开首页，定位"审核通过"行 |
| 2 | 点该行"详情"（`a[href="javascript:;"]`） |
| 3 | 等详情页加载 |
| 4 | 点"上架"按钮 |
| 5 | 预约弹窗点"今日" |
| 6 | 点"预约" |
| 7 | 确认成功，返回继续 |

翻页：从 min(5, 总页数) 往前到第 1 页（保证先通过的先上架）。每页处理完刷新复查。

---

## 5. Batch：批量发布

迁移现有 `batch_all.py` 的分批+断点续传+失败重试：
- `publish-cli batch --start N --end M`：发布 episode_N 到 episode_M
- 每 5 弹分批（避免 10 分钟超时）
- `_batch_total.json` 记录跨批结果，`--resume` 续传
- 失败弹次自动重试 `--retry` 次

## 6. PublishConfig

```python
@dataclass
class PublishConfig:
    # 固定配置（迁移自现有 skill，都可覆盖）
    copyright: str = "捞鱼真不吃鱼"
    thanks_text: str = "谢谢你喜欢我~"
    category: str = "卡通表情/其他"
    style: list = field(default_factory=lambda: ["软萌可爱", "日常"])
    theme: str = "万能通用"
    region: str = "全球"
    accept_tips: bool = True
    # 赞赏图（默认你的，可自定义）
    tip_guide_img: Path = 赞赏页/赞赏引导图.png
    tip_thanks_img: Path = 赞赏页/赞赏致谢图.png
    # 登录
    account: str = None   # 从 .env 读
    password: str = None  # 从 .env 读（base64）
    storage_state: Path = ~/Library/.../publish_storage.json
```

## 7. 命令清单

```bash
# 单弹发布
publish-cli publish --dir <episode_dir>

# 批量发布
publish-cli batch --start 19 --end 54
publish-cli batch --start 19 --end 54 --resume
publish-cli batch --only 23,51

# 自动上架
publish-cli shelf
publish-cli shelf --limit 3

# 登录态管理
publish-cli login          # 手动触发登录（首次）
publish-cli logout         # 清 storage_state
```

## 9. 风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| 微信平台改版导致选择器失效 | 高 | selectors.py 集中管理；text 选择器比 class 稳；失败截图+保现场 |
| playwright 未装 | 中 | C 独立 pip install playwright + browser，不影响 A/B |
| 真实平台测试需要你的账号 | 中 | mock 测试先做，真实冒烟你回来手动跑 |
| 含义词重复/数量不对被平台打回 | 中 | 提交前本地校验（复用 A 的 Gate2 逻辑思路） |
