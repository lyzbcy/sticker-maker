# 同账号跨电脑资源共享设计

日期：2026-09-08

状态：用户已确认完整交付，当前在隔离分支实现并进行回归验收

环境：Windows / macOS，使用 Syncthing 同步资源目录

## 1. 目标与交付范围

在 Windows 制作、整改或提交作品后，可以切换到另一台电脑继续管理同一微信账号。没有原文件也能看到平台作品；连接共享库后自动补齐资源关联，继续修改和提交。所有能力作为一次完整交付，不把占位符当作最终交付。

交付包含：账号作品库、平台占位符、超级备份导出、资源迁移及可选源文件清理、超级导入、持续连接共享库、跨系统路径解析、同步不完整检测、版本冲突处理、账号校验、共享删除与恢复、旧数据兼容。

Syncthing 负责传输文件，应用负责理解作品、资源、版本和账号关系。不新增云服务器，不同步密码和浏览器登录态，不自动修改用户 Syncthing 配置。

## 2. 当前代码与需要改变的边界

- `cli.py:cmd_list_episodes` 扫描本机 `episodes/episode*`；没有目录的作品不会进入列表。
- `publish/platform_data.py:_match_rows` 优先按平台 ID 匹配，未匹配条目仅返回给前端，没有建立作品记录。
- `config/series.py:EpisodeMeta` 有平台作品 ID 和审核历史，没有资源库作品 ID、账号归属或资源可用性。
- `config/paths.py` 可通过环境变量整体切换用户数据目录，但会连同设备相关数据一起切换，不适合作为共享库的最终入口。
- 自定义 base、横幅、封面、图标、系列角色素材映射等含有绝对路径；`series.json` 为整表覆盖写入。
- `cmd_shelf_passed` 的上架操作使用平台作品 ID 和平台详情，不上传原图；可扩展到占位符。
- `cmd_delete_episode` 当前物理删除目录并可能回滚编号，共享模式下必须另行定义。
- 前端以 `complete` 决定详情、提交等能力，需要改为按具体操作判断资源要求。

保留现有 Electron → JSON-lines CLI → Python 引擎调用链。资源业务抽到独立模块，避免继续把存储、迁移和冲突逻辑塞进 `cli.py`。

## 3. 使用流程

### 3.1 一键更新与占位符

1. 确认当前登录的平台账号归属，完整获取作品列表。
2. 按账号和平台作品 ID 更新已有记录；没有匹配记录时新增占位符。
3. 占位符保存平台名称、状态、统计、更新时间、可获取的当前驳回理由，不假造生成时间、系列编号或历史审核轮次。
4. 重复更新不新增重复作品；同步失败或只返回部分列表时，不据此删除已有记录。
5. 用户没有连接共享库时，占位符保存在本机账号作品库。连接后按身份合并；资源到达后自动关联，列表仍是一条作品。

“查看状态/理由”“上架”“编辑素材/重提”分别判断权限。占位符可打开详情；审核通过作品可在登录账号和最新平台状态核对后执行上架。新建提交和整改重提必须通过对应素材校验。

### 3.2 超级导出

选择目标文件夹后显示作品数、可复制容量、缺失资源及账号分组。目标已是资源库时进入合并流程，不能覆盖整库。

两种用途明确区分：

- **备份导出**：生成完整可导入的资源库副本，当前读写位置不变。
- **迁移并使用新位置**：校验复制结果后持久化新位置，之后读写新库。可勾选“成功迁移后清理旧位置中的作品文件”，默认不勾选。

导出完整作品目录，包含原图、成品、切图及处理结果、横幅/封面/图标、介绍、含义词、可恢复制作所需记录；收集作品和配置引用的外部自定义素材、base、参考图库及归档、自定义提示词、系列配置、共享制作偏好。应用内置资源由版本标识引用；用户自定义资源必须实际收集。

只收集已知数据根及显式引用的外部文件，不扫描整机原图目录。外部路径不存在时记录缺失，允许用户补选正确位置；无法取得的文件不得报告迁移完成。

凭据、Cookie、浏览器目录、API 令牌、Codex 登录配置、设备启动配置、日志缓存不进入资源清单。制作偏好用允许列表导出，不能直接复制全部用户数据目录。作品历史日志中含有的旧路径可作为历史文本保留，但不能继续充当有效资源引用。

### 3.3 超级导入与持续连接

- **连接共享资源库（推荐）**：选择本机 Syncthing 同步到的目录，识别库 ID，建立本机路径映射，校验并合并作品。后续自动发现到达的新版本，提供手动刷新入口，不要求反复导入。
- **复制导入到当前库**：把备份或其他库的内容合并到当前库，不修改来源库。保留作品与版本身份，重复导入不重复复制。
- 导入目标存在同身份的不同内容时进入版本合并规则。不能用目录名、作品名称或文件修改时间直接判定覆盖关系。
- 导入旧版 `StickerEngine` 数据目录时，先生成迁移预览，再规范化路径及身份；不在预览阶段修改源数据。

Windows 的 `D:\共享\表情资源库` 与 macOS 的 `/Users/.../共享/表情资源库` 可以对应同一个库 ID；各机仅记录各自实际路径。

### 3.4 日常使用与切电脑

在 A 电脑完成生成或整改后，应用提交一个资源版本。B 电脑收到且验证该版本资源齐全后，可接着使用。列表显示本机可用版本和最近发现的版本，不把“本机保存成功”显示成“其他电脑同步完成”。

提供“准备切换电脑”：结束当前批次、持久化作品版本和操作记录，展示“已保存到共享目录，请等待 Syncthing 完成同步”。本次不接入 Syncthing 管理 API，因此不宣称知道远端是否最新。B 电脑展示实际已接收并验证的内容，由用户核对 Syncthing 完成状态后接手。

多电脑可各自制作不同 UUID 的草稿；同一作品并发修改保留分支。日常串行切换发布电脑。纯文件同步无法保证分区期间跨设备互斥或平台提交恰好一次，界面和验收不得承诺这些能力。

## 4. 数据组织与身份

### 4.1 本机与共享数据分离

本机应用目录保留：设备 UUID、资源库位置、当前账号选择、系统凭据、登录态、可重建索引、迁移任务日志及工作暂存区。共享库存放作品版本、资源内容和共享配置。

建议目录：

```text
共享资源库/
  library.json                      # 库 ID、格式版本；创建后不频繁改写
  objects/<sha256前缀>/<sha256>       # 内容寻址的不可变文件
  accounts/<account_id>/
    binding/<binding_revision>.json  # 账号绑定的版本记录，不含密码
    works/<work_id>/revisions/<revision_id>.json
    settings/<entity_id>/<revision_id>.json
    operations/<device_id>/<operation_id>.json
```

版本清单包含格式版本、作品 ID、账号 ID、版本 ID、父版本集合、设备 ID、资源相对路径到内容哈希及大小的映射、元数据、生成或编辑状态。共享目录不存放多机共同写入的 SQLite，也不依赖一个不断覆盖的总索引或 `HEAD.json`。

每次生成和修改先进入本机工作目录，成功保存后写入共享对象和新版本。原有引擎所需的“原图/最终版/横幅”等目录通过资源访问层解析或暂存成现有结构。读取原文件以当前资源库为准，暂存是可清理缓存，不能依赖迁移前的 C 盘文件。暂存不得与不可变对象硬链接后原地修改。

“打开作品文件夹”提供具有原始文件名和目录结构的可读副本；用户手工改完后，通过“收录修改”生成新版本，不能直接编辑对象库。暂存容量单独显示，可清理已结束任务的缓存；迁移预览计入暂存空间需求。

### 4.2 账号与作品身份

- 库、账号和未发布作品各有 UUID；已发布作品的外部身份为 `平台类型 + account_id + platform_item_id`。
- 平台能可靠取得稳定账号标识时用于验证绑定；具体字段需在开发时做只读实测，当前资料不足以指定字段。
- 若平台暂不能提供稳定 ID，则以用户明确绑定的平台登录账号作为验证依据；展示昵称不能独立充当身份。不能验证当前登录账号时暂停平台写操作，要求重新登录并核对绑定。
- 同一共享库在不同设备复用已有账号 ID。导入其他库时，可通过已验证的平台身份合并账号；证据不足则提示用户选择归属，不按昵称自动合并。
- 老作品账号归属未知时列入“待绑定”；预览并确认绑定后才允许同步写入其平台状态或发布。
- 旧作品首次匹配可使用同账号下唯一的完整规范化名称，歧义留待关联；已建立平台 ID 后以 ID 为准。
- 相同平台身份对应多个历史 UUID 时保留关联及版本，列表归并为一个逻辑作品，资源差异进入冲突处理，不丢弃历史。

### 4.3 路径与资源收集

可执行的引用统一变为库内资源标识或 POSIX 风格相对路径，运行时映射成本机路径。外部自定义文件迁移后使用已收集的副本。导入拒绝绝对路径、`..` 越界、Windows 保留名称、大小写冲突等不可移植清单；符号链接默认不跟随，列入待处理，不能借导入越过目标目录。

仅平台记录、本机资源不可用、资源可用、制作未完成、版本冲突分别表示不同情况。平台审核状态与资源情况独立。单个 PNG 存在不能代表“可提交”，按发布要求验证数量、素材和文字数据。

## 5. Syncthing 一致性与冲突

### 5.1 到达顺序与完整性

文件传输顺序不受应用控制。版本清单即使最后在 A 写入，也可能先在 B 到达。B 必须确认所有引用对象存在且大小和 SHA-256 正确后才激活版本。

父版本尚未到达时，版本图不完整，标记待同步，不能误判为独立新作品或已解决冲突。非法父引用、自引用和循环引用隔离报错。已验证对象可缓存校验结果，使用前检查文件变化；文件改变必须重新验哈希，不能永久信任缓存。

清单或对象没到齐：显示“资源未到齐，等待同步”，保留上一完整版本供查看。若已发现更新版本但不完整，禁止基于旧版本直接重提该作品；用户可等齐或明确建立独立草稿。共享目录失联时保留本机索引，不把失联当作清空作品库，也不自动创建同名新库。

忽略 Syncthing 临时文件作为业务输入。发现 `sync-conflict` 文件时隔离并展示，不自动当作正常版本。对象同哈希但内容校验失败视为损坏，禁止使用，提供从备份或其他副本恢复入口。

### 5.2 并发版本

每个新版本引用实际编辑所基于的父版本。到达版本若为已知版本的后代可正常推进；同一作品出现互不为祖先的有效版本，则保留两者并标记冲突，不用电脑时间或文件时间决定胜者。

冲突页展示来源设备、修改字段、资源缩略图和历史，支持选用某版本或另存为草稿。选择某版本会创建同时引用冲突父版本的新合并版本，原版本仍保留。平台 ID 不随“另存为草稿”复制，防止两个草稿操作同一平台作品。

系列、角色与自定义配置按实体版本化，避免整份 `series.json` 相互覆盖。参考图“已使用”通过追加的使用记录取并集，禁止一个设备归档动作删除另一个设备仍需的共享对象。

### 5.3 系列编号与平台写入

共享库中系列编号依据已见作品占用情况分配，不回滚到已见已发布作品占用的编号。离线并发可能产生同号草稿，合并时明确标记；发布前再次检查本地冲突和平台现有名称，用户解决撞号后再提交。UUID 始终是草稿身份，不能把展示编号当身份。

同机生成、迁移、整改、账号切换和平台操作按资源范围互斥；平台写操作保持同机串行。远端活动记录仅作提示，不作为可靠锁。

发布前核对账号、平台作品 ID、平台当前状态和所选资源版本。平台提交操作使用唯一操作 ID 记录意图及结果，但不把它冒充平台支持的幂等键。断线或超时后记录“结果待核对”，先对账，不自动重试提交。另一设备尚未收到该记录时仍存在竞态，靠串行交接的使用约束控制，不能宣称完全消除。

平台当前状态以本次平台读取为准；跨设备审核历史按操作 ID/观测身份合并。证据不足的审核轮次沿用未知标记，不因导入复制或重复观察增加伪造轮次。

## 6. 迁移、清理与恢复

迁移执行顺序固定：

1. 创建只读扫描清单，确认源与目标不是同一路径或互相包含，检查空间与写权限，列出外部依赖和缺失项。
2. 停止本机相关写入任务，按清单复制；记录每项大小与哈希，支持取消和断点续作。源在扫描后发生变化则重新校验，不能清理变化后的源。
3. 验证目标全部所需资源和清单，缺失时保留旧库为活动库。
4. 原子替换本机资源库配置，重新加载引擎与资源解析器；验证列表、详情、素材读取及下一次生成的输出位置。失败回滚配置，保留源。
5. 仅在用户本次勾选清理且前述步骤成功后，清理清单中已确认复制成功、未变化、由应用管理的旧作品文件。外部被引用的原文件只收集，不自动删除，避免影响其他项目。
6. 清理失败不伪报全部成功；保留新库可用状态和剩余清单，可继续清理。任务记录持久化，崩溃重启后能判定处于复制、切换或清理阶段。

目标本机校验成功只说明 D 盘副本完整，不代表其他电脑已经同步。迁移结果分别展示本机完成状态与“远端同步状态未知”。旧目录如果本身处于 Syncthing 同步范围，清理预览明确标出会传播的删除范围；不删除 Syncthing 管理文件，不清空整个共享目录。

占位符无原文件可导出，只导出记录并如实计数。原文件缺失和平台占位符不同，不能混为“完整迁移”。

删除分三类：本机隐藏记录、本机清理缓存、从共享库移除作品。共享移除创建可同步的删除版本，资源保留供恢复；删除与编辑并发视为冲突，不能默默抹掉新编辑。旧设备收到删除版本后不把旧记录自动复活。本次不自动永久清除共享历史对象；永久回收需要可证明的引用与设备同步边界，不能靠一个离线设备看见的状态推断。

## 7. 界面与接口

设置新增“账号与资源库”，展示当前账号、当前库位置、已连接库、作品/资源情况，提供超级导出、超级导入、刷新资源、打开目录、冲突处理、准备切换电脑入口。

迁移向导：用途与目标 → 扫描结果和可选清理范围 → 执行进度 → 结果与缺失/失败清单。开始前预览具体源路径和目标路径；交互确认属于产品功能，不意味着开发期间可以实际清理用户文件。

作品列表展示独立的资源标签；详情页分开展示平台数据与资源数据。版本未齐或冲突时，明确解释为什么某项操作不可用，并提供等待刷新、补选资源、处理冲突入口。

CLI 新命令按职责提供库扫描、迁移预览/执行/恢复、导入预览/执行、连接/刷新、账号绑定、冲突查询/解决、删除/恢复；沿用请求 ID、进度、取消和明确错误结果。预览生成计划 ID，执行前复核路径和清单，不能接受前端直接传入任意删除清单。

模块边界：

- `library/catalog`：账号、作品身份、版本图与列表查询，本机索引可重建。
- `library/resources`：相对路径、对象校验、现有引擎所需目录的解析与暂存。
- `library/transfer`：扫描、复制、校验、切换、清理、任务恢复。
- `library/reconcile`：版本合并、占位符关联、删除记录、冲突及系列占用。
- 发布模块：只通过账号上下文和选定版本执行平台操作，沿用真实成功判据。

旧 CLI 入口经兼容层解析本地旧作品或库中作品，新界面使用作品 ID。旧数据默认不自动搬家；首次启用迁移时才生成库格式。不可识别的新格式只读报错，不能按空库覆盖。

## 8. 实施顺序与验收

一次完整交付，内部按依赖实施：资源与身份层 → 旧数据适配和占位符 → 导出/迁移/导入 → 版本同步与冲突 → 发布与删除适配 → 桌面交互 → 双端验收。各阶段持续回归现有制作与发布逻辑。

必须覆盖：

1. 新电脑无本地作品，一键更新后所有已完整读取的平台作品可见，重复同步不重复。
2. 两账号同名作品互不污染；未知账号和账号不一致时不能写平台。
3. Windows 旧库导出后，macOS 可解析所有实际收集的资源；无需访问源电脑路径。
4. C 盘迁至 D 盘后，重启仍读取 D 盘，新作品落到 D 盘库；取消、磁盘满、文件变化或校验失败均不删除源。
5. 执行切换或清理途中崩溃，恢复后不会重复清理目标库或扩大删除范围。
6. 同一库多次导入不重复；占位符与资源正确合并；同名异作品保留。
7. 模拟清单先到、对象后到、父版本后到、损坏对象、冲突文件、目录暂不可用，都不把未完整版本激活成可发布资源。
8. 两机并发修改同一作品保留两版本，解决冲突可传播；离线同号草稿不在合并时静默覆盖。
9. 平台审核历史导入和重复同步不伪增轮次；发布结果不确定时不得盲重试。
10. 占位符可看理由和详情；无素材的审核通过作品能经核验上架；需要上传的操作正确阻断缺素材情况。
11. 共享删除可恢复；删除与新编辑并发有冲突提示；本机隐藏不会删除共享文件。
12. 导出清单不包含凭据、Cookie 或设备配置；中文路径、空格、长路径、跨系统名称冲突和越界输入有测试。

运行项目规定的后端 pytest 和前端 vitest，并完成桌面构建与界面走查；现有未提交的平台同步改动纳入兼容验证，不覆盖用户工作。自动化测试用临时目录模拟乱序与多设备副本，不触碰真实原文件。

Windows/macOS 两机真实 Syncthing 交接必须单独记录：实际传输、资源校验、迁移后重启、并发冲突处理。当前环境无法执行的 Windows 或平台写入验收明确标记为未验证，不用模拟测试替代真实通过记录。

## 9. 已确定的取舍

- Syncthing 默认使各电脑持有文件副本；迁移能释放旧盘空间，不能承诺其他电脑零落盘。占位符满足不连接原文件库的管理需求。
- 不用共享文件锁实现分布式互斥，不用文件修改时间自动覆盖冲突。
- 不直接同步整个应用数据目录；原文件与制作配置共享，登录与设备数据本地保留。
- 不假设收到本地目录就是已与所有设备同步，也不自动重试结果未知的平台提交。
- 通过不可变资源和版本记录保留冲突与恢复能力，相应会保留历史占用；本次不自动永久清除共享历史。


## 10. 实现落点与验收边界（2026-09-08）

实际共享布局统一使用 `accounts/<account_id>/works/<entity_id>/revisions/`。
`metadata.kind` 区分作品、设置实体和平台操作记录，复用同一套不可变版本图；
账号 ID 按明确绑定的平台登录账号规范化后计算，设备 ID 和路径映射仅存本机。
这取代第 4 节建议目录中的独立 settings / operations 子树，保持相同的数据隔离目标。

迁移后，可编辑工作目录和设置投影放在目标库相邻的
`.sticker-maker-workspaces/<device_id>/<library_id>/<account_id>/`，从而不继续依赖旧系统盘的大体积缓存。
Syncthing 只同步资源库目录；如果同步的是父目录，必须排除这个工作目录。
旧位置中的小型目录元数据和配置投影可保留；可选清理针对已验证的原资源及应用生成的资源副本。

发布账号、密码与浏览器登录态仍由每台设备单独维护。首次绑定必须填写与发布设置相同的登录账号。
本功能不安装或自动配对 Syncthing，也不通过其 API 推断远端状态。

验证采用临时资源和独立设备目录，含真实 JSON-lines 引擎进程重启。
Windows/macOS 两台物理电脑之间的 Syncthing 实际传输和真实平台提交不属于模拟测试通过的结论；
这些仍需在真实设备与账号上进行验收。具体操作见 `doc/reference/resource-library.md`。
