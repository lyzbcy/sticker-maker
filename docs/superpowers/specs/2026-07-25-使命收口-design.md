# 表情包一键制作 · 使命收口设计

> 日期：2026-07-25  
> 依据：`.openclaw/初心与使命.md`  
> 原则：使命文档高于既有 A–E 子项目的范围缩减和“已交付”自报。

## 1. 审计结论

现有 Electron + Vue 桌面壳、Python 生图管线、微信发布器、AI Agent HTTP 服务和推广资源具备可复用基础，不重写技术栈。当前主要问题不是“没有代码”，而是若干能力彼此割裂，普通用户无法从软件内完成使命描述的闭环。

本轮必须关闭以下缺口：

1. base 图虽可上传/生成，但全部混入“自定义”角色，缺少角色归属和每张 base 的概率配置。
2. 多人模式只向生图端传一张 base 图，无法可靠保留多个角色身份。
3. `reference_lib_path` 保存后丢失或要重启才生效。
4. 角色概率与 base 概率在界面和引擎之间没有完整校验、同步和持久化。
5. 发布器和 Agent 服务虽有独立代码，却没有成为桌面软件内可发现、可操作的功能。
6. 50 条日志只存在于单次管线上下文，用户无法查看，也不能覆盖桌面桥接、发布和 Agent 状态。
7. 安装脚本只提示用户手动拖拽；更新器只打开下载页，不符合“一键”目标。
8. 介绍页宣称“一键发布/Agent 接口”，但桌面端尚未真正提供这些入口；版本页也未形成单一版本源。

## 2. 方案比较

### 方案 A：在现有双进程架构上收口（采用）

- Electron 负责窗口、文件选择、安装更新和用户界面。
- Python CLI 继续作为常驻业务进程，统一暴露生图、发布、Agent、日志命令。
- 现有微信发布器、Agent 服务和测试直接复用。

优点：改动集中、现有测试可回归、Windows 仍可沿用 Electron + PyInstaller。缺点：发布浏览器依赖仍需在真实微信平台做冒烟验证。

### 方案 B：改写为 Tauri + Rust

包体更小，但要重写桥接、安装更新、Python 分发和大量 UI；本轮风险过高。

### 方案 C：改为本地 Web 服务 + 浏览器界面

AI 接口自然，但普通用户安装、权限、浏览器会话和更新体验更差，不符合 `.app` 交付要求。

## 3. 目标架构

```text
Vue 界面
  ├─ 首次向导：Codex → 角色/base → 人数概率 → 角色概率 → 模式偏好
  ├─ 大本营：生成、历史、精选、发布、Agent、日志
  └─ 设置/关于：全部偏好、三码、版本
          │ IPC（结构化命令/进度）
Electron 主进程
  ├─ PythonBridge（常驻、崩溃恢复）
  ├─ 文件/目录选择与本地图片 URL
  └─ 安装与更新
          │ JSON Lines
Python sticker-engine-cli
  ├─ 生图管线（Codex / 裁切 / 抠图 / 素材）
  ├─ 微信发布器
  ├─ AI Agent HTTP 服务与调度器
  └─ 50 条内存环形日志
```

## 4. 数据与流程

### 4.1 角色和 base

- 自定义素材保存为 `custom_bases/<角色名>/<图片>`，兼容旧版根目录素材并映射为“自定义”。
- 上传和 AI 生成都必须携带角色名。
- 每个角色的 base 概率必须覆盖现有 base，保存时总和为 100%。
- 单人角色概率总和为 100%；多人模式用同一权重做不放回抽样。
- 多人模式为每个选中角色各选一张 base，按角色顺序全部传给 Codex。

### 4.2 生图模式

- 参考图库足量时按开关优先；保留参考图背景。
- 否则在故事模式与排列组合模式间选择。
- prompt 模式固定 `#ff00ff`，禁止背景阴影；后处理自动抠图。
- 1×1 不切图；2×2、3×3、4×4 自动切图。
- 故事顺序写入 `meaning_map.json`，发布器按该顺序上传。

### 4.3 发布

- 生成结果页和历史作品均提供“提交到微信”入口。
- 发布前做素材、运行依赖和登录态预检；长任务显示步骤和结果。
- 首次登录打开可见浏览器；登录态保存在用户数据目录。
- 平台选择器变化或真实平台限制必须返回可行动的错误，并保留现场截图路径。

### 4.4 AI Agent

- 软件启动后可由用户一键启用本地 `127.0.0.1:7432` 服务。
- 界面展示连接地址、token、提示词，并支持复制。
- 支持查询、生图、停止、发布、批量、上架和定时任务。
- 默认仅监听 loopback，除健康检查和提示词外均需 Bearer token。

### 4.5 日志

- CLI 内维护全局 50 条环形日志，不写磁盘。
- 记录命令开始/完成/失败、进度、桥接重启、发布和 Agent 状态。
- 软件内提供日志面板和复制按钮；敏感 token、密码不得进入日志。

### 4.6 安装与更新

- zip 内包含 `.app` 与 `install.command`。
- 安装脚本自动去隔离、复制到 `/Applications`（必要时请求系统授权）并启动。
- 软件检查 `version.json`；发现新版本后可下载并启动同包内安装流程。
- `package.json`、CLI、介绍页和 `version.json` 使用同一版本号。

## 5. 错误处理

- 所有跨进程命令返回 `{status, data, errors}`；界面不依赖 stderr 文案解析。
- 概率、路径、角色名在界面和 Python 两层校验。
- Codex、发布浏览器和 Agent 依赖分别预检，失败只阻断对应功能。
- 长任务可取消；无法即时中断的外部调用应明确显示“正在结束当前步骤”。
- 更新检查离线时不打扰用户，但手动检查必须展示失败原因。

## 6. 测试与验收

1. Python 单元/集成测试覆盖多角色多 base、持久化、日志、发布命令和 Agent 生命周期。
2. Vue/桥接测试覆盖概率校验、发布入口、日志和 Agent 状态。
3. Vite 生产构建成功。
4. PyInstaller 产物可启动并加载内置角色、精选资源及新增命令。
5. Electron 可生成 macOS `.app`，zip 含 `.app` 与可执行安装脚本。
6. 安装脚本做静态和临时目录冒烟测试，不覆盖用户现有应用。
7. 不声称微信真实提交成功，除非在真实平台完成冒烟；未冒烟要在界面和交付说明中明确标注。

## 7. 非目标

- 本轮不制作 Windows `.exe`，但不得引入只适用于 Mac 的核心业务路径。
- 不绕过微信平台验证码、审核或其他安全机制。
- 不把 Codex token、微信密码、Agent token写入项目或日志。
