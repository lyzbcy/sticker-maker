# 网页生图与质量细节

使用宿主浏览器能力控制用户指定的 ChatGPT 网页。先确认登录和正确对话；一次生图任务一个独立对话，记录URL续接。

上传必须通过页面真实文件输入或系统选择框。确认有角色附件，上传计数和文件名正确。Kimi扩展在Windows可能要求用户打开「允许访问文件网址」；遇到该明确错误才说明操作。其他宿主不要求安装Kimi。不可用创建空input、打印文件名等方式假装上传成功。

提示词需包含：唯一角色base身份，单人/双人，恰好4×4均匀分格、每格完整留白、16个不同动作与可读中文短字。背景选纯洋红#ff00ff，角色含洋红时改纯绿#00ff00并同步传给后处理 --key；禁止地面/投射阴影、渐变、纹理。立体感由材质本身明暗表现。双人明确A/B身份及互动。图片外观由参考图约束，不给文字重新发明人物。

生成时等待本次助手图片真正加载；停止按钮消失通常只表示响应结束，还要检查错误、图片自然尺寸和真实文件。不可将base附件、历史图片或「正在生成」缩略图作为本轮产物。每30—60秒检查一次即可，长时间失败保留现场。

下载优先页面下载原图按钮。若通过页面图片资源取回，必须确认资源属于当前助手生成图片并以图像解码验证，记录原字节与转换；不要把截图放大冒充原图。源链接可能含临时签名，不放入公开文档。

后处理直接导入当前一键制作表情包引擎的 grid_cutter.py / chromakey.py，不携带复制快照。切图诊断出现等分兜底、跨格等，必须查看预览再决定是否接受。

## 同一次响应输出含义词，复用审图

首次生图提示词同时要求：生成图片后，在同一次响应附上JSON，按左到右、上到下输出1—16的 index、实际图中文字 text、建议含义 meaning；无字格的text为空。不要为取表格单独追加一轮请求。模型未给JSON时保留原图，在必要的整图审阅中记录即可，不重生图片。

JSON只是候选：生成时可能换词或顺序，不能视为图片真值。将编号映射显示在原本就要看的分格预览中，同一次审图确认文字、画面、顺序与边缘，修正异常格并写 meanings.json。无异常不再发起独立识图；只有小字看不清等异常才局部放大或按需识读。脚本核对16个索引、唯一性、文件映射，不能证明图中文字正确。
