## 目标
要做自适应更新，就需要进行版本号管理。具体流程与功能设计如下：

1. 版本号更新机制：
在软件对应的开发 Skill 中写好，每次更新完之后，都要更新一下版本号，并同步更新到远端仓库。

2. 版本检查机制：
软件每天首次使用时，检查本地版本号是否与远端一致。如果不一致（落后于远端），则提醒用户更新。

3. 一键更新功能设计：
由于我们的仓库一般放在 GitHub，一键更新需要做到“小白友好”，所有人点一下就是真的“一键更新”：
(a) 自动重启：该自动重启的网关等设备，帮用户自动重启一下。
(b) 代理提醒：建议用户在国内开启代理，这样一键更新会比较快。
(c) 进度展示：更新时要加进度条，让用户可以直观地看到更新进度。

4. 异常兜底方案：
如果更新超时或失败（可能是用户网络不好或其他原因），需要有兜底方案：
(a) 提示重试：提示更新失败，可以下次重试。
(b) 跳转下载：提供一键跳转到发布页的操作，让用户去重新下载最新版本。

## 实现与发版核对（2026-09-30 补充）

### 必须区分的能力

- 维护版本号、推送 Git：只是开发与备份流程。
- 查询产品最新发布：可以更新下载信息，但不代表读取了本机安装版本。
- 软件自身更新：需要真正比较当前运行版本与远端版本，并提供提醒、下载、安装和恢复流程。

在项目 SKILL.md 和更新模块文档中分别记录实现状态、代码入口与验收证据。仅写了规范、查到远端版本或找到主 exe，都不能算完成自身更新。

### 运行要求

1. 明确“每天”的时区；自动检查记录尝试与成功日期，断网不能被标为检查成功，也不能每次打开都高频重试。保留手动检查入口。
2. 按版本字段比较，不能用字符串字典顺序（例如 0.10.0 应高于 0.9.9）。只有远端正式版本较新才提醒，避免降级或默认升级到预览版。
3. 更新地址与包类型由受信任的配置确定。下载后验证原始包 SHA-256，校验失败不执行；临时文件和旧版本分开存放。
4. 用户点击更新后展示进度，失败提供重试与发布页回退。国内 GitHub 连接较慢时给代理/换线路提示；已有线路测速方案可复用，不必每个项目另建后端。
5. 下载校验完成后再退出旧版；安装 helper 等旧进程退出后安装，确认安装结果再启动新版。保留用户数据、设置和原安装目录；升级成功前保留恢复手段。
6. 没有更新器的旧客户端无法靠发布新版获得更新能力，需要说明先手动安装一次的迁移步骤。

### Windows 安装重启经验（仅适用 Windows 项目）

- 后台 helper 和静默安装器可以隐藏；重新打开的软件是交互应用，需要正常可见窗口。验收不能只看进程存在，还要确认窗口可见、路径和版本正确。
- 从 PowerShell 7 或其他宿主启动 Windows PowerShell 时，继承的 PSModulePath 可能使 Get-FileHash 不可用。关键哈希复核可直接使用 .NET SHA256，避免依赖该脚本命令；跨进程参数使用结构化数据，不能拼接任意用户命令。
- 同一安装包保持不可变：包改了就递增版本并重新计算哈希，不覆盖已经发布的同版本文件。
- 安装后记录成功/失败结果，检查卸载登记的版本和安装路径；失败不误报已升级，并向用户说明重试方式。

### 发版与验收

- 先上传并核验最终版本包，再发布指向该包的更新元数据；仅推送源码不能让客户端检查到新版。
- 单元测试覆盖版本比较、同版/降级、网络失败与手动重试、错误哈希和重复点击；再用真实安装包验证安装、重启和数据保留。记录模拟测试与实际验收的范围。
- 公网回读更新信息和下载入口，核对版本、文件名和哈希；按已有授权备份源码，保持仓库既定可见性，凭据不进入客户端或仓库。

已落地参考：`E:\共享\创业\捞鱼软件中心\SKILL.md` 与 `docs/updater.md`，正式版 0.7.2。该案例仅证明启动器自身更新已经实现，不代表所有既有软件都已接入更新器。

## Windows 助手交接故障（2026-10-02 补充）

- 不要用 detached:true + stdio:ignore + windowsHide:true 直接启动 Windows PowerShell；实际 Electron 环境可能返回退出码 0 但没有执行脚本。
- 也不能仅改 detached:false：父进程退出可能结束直属子进程。使用隐藏的短引导器，通过 Start-Process 创建独立助手，然后等待引导器退出和助手就绪确认。
- 引导器不要给助手使用 RedirectStandardOutput/Error：PowerShell 可能等待后代输出任务，导致双方等待。助手自身将错误记录写入文件。
- 参数写入独立尝试目录，使用随机 token 的 ready/commit/abort 握手。未收到有效就绪确认不能退出旧软件，启动失败应保留窗口。不要将 spawn 或退出码 0 等同于已开始安装。
- PowerShell -File 读取中文脚本需要明确 UTF-8 BOM；短 EncodedCommand 引导脚本可调用文件并捕获解析错误，避免嵌套超长命令行。
- 发版必须验证真实安装版完整流程：点击更新 → 下载校验 → 旧进程退出 → 实际安装 → 自动打开可见新版 → 桌面重新打开仍为新版，并核对随机安装 ID、设置和软件关联保留。回归标记/开发模式冒烟不能代替这个验收。
- 旧版固化了错误启动逻辑时，先手动安装修复版一次。不要只替换远端元数据后宣称旧用户已经能自动修复。
- 打包必须等待压缩器完成再计算最终哈希并上传，禁止并发读取还在写入的发行包。

参考：捞鱼软件中心 src/update-handoff.cjs、src/install-update.ps1、scripts/verify-installed-update.cjs 和 docs/updater.md。
## 产品下载查新与缓存（2026-10-02）

- 每次下载先查询该产品最新发布，随后再决定是否复用本地包。已有缓存和哈希不代表仍是最新版；删除软件/ZIP 后也必须查新。
- 使用跨版本资源名前缀/后缀或严格模式，拒绝写死带版本号的资源名；多个匹配资源时停止。
- 预发布渠道必须按产品明确配置，不能默认所有软件接受预发布。查询失败不悄悄退回旧包，UI 明确缓存和本地旧包状态。
- 备用校验值只用于同版本、同资源名、同 URL；下载及测速统一遵循系统代理。
- 验收必须种入真实旧缓存，再从界面点击下载，核验实际最新包、完整 SHA-256、解压主程序及打开入口。不能以 API 查询成功代替下载验收。
参考：软件中心 0.7.8、src/release.cjs 和 scripts/verify-product-download.cjs。
