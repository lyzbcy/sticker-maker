## 目的
咱们自己的静态网页，无论是部署在 GitHub 上还是部署在 help.wshoto 上，都会存在缓存问题。因此，对于这类网页的开发，每次开发完之后都需要更新一下版本号。远端也会有一个版本号，每次打开网页时：

首先，要去核对当前版本号和远端版本号是否一致，如果不一致，就强制刷新一次。

当然，这样做也有问题。如果版本号管理得不好，就会出现一直重复刷新的情况：用户一打开网页，系统检测到有问题就刷新；刷新后又刷不到新的版本号，于是就一直刷新、一直刷新、一直刷新。这个问题你想办法解决一下。关于“一键刷新”功能，一般可以配合更新日志来做：

1. 新增更新日志组件：
你可以做一个更新日志的小组件，放在合适的位置（比如左上角或右上角），显示最近一次的更新记录和更新内容。

2. 优化一键刷新按钮：
(a) 按钮位置：在组件旁边放一个“一键刷新”按钮。不需要做二级菜单，直接放在一级菜单，按钮本身就是触发刷新的。
(b) 交互提示：用户可以滑到旁边查看最近更新日期，然后直接点击“一键刷新”。
(c) 提示文案：因为静态网页经常会有缓存，为了获取最新消息，可以提示用户：“请勤点击一键刷新，经常点点一键强制刷新。”

## 参考实现（2026-09-15）

- 位置：JNU-Toolkit/docs/index.html（民主测评打分页）+ 同目录 version.json
- 远端版本：version.json（fetch 时带 ?t=时间戳 防缓存），页内常量 PAGE_VERSION
- 防无限循环方案：sessionStorage 记录『已为目标版本 X 刷新过』，同一目标版本每会话最多自动刷新一次；即使刷新后拿到的 HTML 仍是旧缓存，也不会二次刷新，用户可手动点一键刷新兜底
- 更新日志：version.json 的 changelog 数组，页头显示最近一条；一键刷新按钮为一级按钮置于右上角
