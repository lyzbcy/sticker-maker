# 捞鱼软件中心适配规范 v1

依据：启动器 0.6.0 的 installed.cjs、portable.cjs、extract-portable.ps1 和 catalog/products.json。最后核对：2026-09-30。启动器实现变更时同步更新规范与自查。

## 最短接入路径

稳定产品 ID → 固定主程序名 → 完整构建包 → 图标/简介/视频 → 同步启动器登记 → 自查 → 实际安装与打开验收。

新建软件时就采用这一流程。无需为了识别而给每个软件加联网服务，也无需扫描用户整块硬盘。

## 产品要提供什么

| 项目 | 约定 |
| --- | --- |
| 产品 ID | 小写英文、数字、短横线，例如 airpods-buddy；发布后不随中文名变化 |
| 主程序 | 固定 basename，例如 AirPodsBuddy.exe；版本写在包名和版本资源里，别写进主 exe 文件名 |
| 应用身份 | 安装器和应用使用稳定 AppID/升级标识；Electron 设置稳定 appUserModelId；更新保留用户数据 |
| 版本 | x.y.z，可带预发布后缀；产品版本独立于启动器版本，沿用项目统一版本源 |
| 发布包 | 明确 Windows/macOS/Linux 与 x64/arm64；禁止把同一个 Windows 包提供给 Mac |
| 下载记录 | HTTPS 地址、真实包名、版本、SHA-256（原始包字节），尽量提供 sizeBytes；GitHub 仓库必须在启动器允许范围内 |
| 视觉资料 | 产品自己的图标；一句话摘要、分类、官网；有真实介绍视频则提供抖音视频 ID，可提供对应封面；没有视频就不编造 |
| 描述文件 | 项目根目录 launcher-adapter.json，用于开发与自查，不是运行时安装证明，不放密钥和密码 |

主程序 PE 头/MZ 检查只能说明基本格式，不能证明包安全、签名有效或真正能运行。正式交付仍需真实运行验收。

## 安装版

- 首选每用户安装 `%LOCALAPPDATA%\Programs\<稳定目录>`；确需全机安装才申请管理员权限。
- Windows 卸载登记写 DisplayName、DisplayVersion、DisplayIcon（主 exe 路径）、InstallLocation、UninstallString。安装器创建指向真实主 exe 的开始菜单快捷方式；更新不能留下指向旧版本的失效链接。
- 桌面快捷方式、安装后打开由用户选择。开始菜单和卸载登记不依赖桌面快捷方式选项。
- 应用设置稳定 AppID，使用自己图标；不要通过偷偷修改系统设置强制固定任务栏，提供用户手动固定指引。
- 主程序埋在版本目录里时，用 DisplayIcon 和开始菜单快捷方式直达它，避免依赖扫描深度。
- `installation.displayName` 是预期安装展示名。脚本检查它是否能通过当前启动器的注册表名称筛选，不会代替安装后的注册表验收。

## 便携 ZIP

- 主 exe 必须在 ZIP 根目录，不要额外套一层软件名文件夹。依赖文件保持原有相对布局，不能只压主 exe。
- SHA-256 对整个 ZIP 计算；软件 ID 必须加入 portable.cjs 的映射。当前只有 AirPods 小助手已登记自动准备。
- 对齐现有解压器限制：最多 5000 条目、声明解压总量最多 512 MiB；禁止绝对路径、`..`、冒号、Windows 非法文件名、设备名、链接和特殊文件。
- 还应避免大小写冲突/重复路径以及文件和目录冲突。启动器使用 CreateNew 写入，重复文件会使准备失败。
- 当前自动准备仅校验、解压和关联，用户点击才打开；更新不覆盖用户自己的安装目录。

## 启动器端必须登记

1. `catalog/products.json`：ID/name/category/summary/kind/siteUrl、iconImage、videos、supportedPlatforms；下载匹配条件（assetName 或 prefix/suffix）、publishedVersion 与 fallbackRelease 的 name/url/sha256/version。
2. `src/installed.cjs`：RULES 的 ID → 主 exe 列表；注册表 DisplayName 正则加入安装名。文件名全量匹配，不区分大小写，不按中文展示名猜。
3. 如需 ZIP 自动准备：`src/portable.cjs` 的主程序映射。
4. 官网详情页、直达链接及启动器深链使用同一个产品 ID；沿用当前深链协议，先核对实现，别自行发明协议参数。
5. 随客户端发布识别白名单；远端 catalog 更新不能给旧客户端添加主程序识别权限。

默认扫描 LocalAppData/Programs、Program Files、Program Files (x86)，深度 2；安装记录目录扫描深度 1；快捷方式深度 2。路径预算有限，便携软件放在任意私有目录时可能需要手动关联。

## 平台与非 EXE 产品

本版自查针对 Windows 桌面 exe/ZIP。macOS/Linux 分平台提供构建和下载记录，按平台独立验收；当前 Windows 启动器的识别验收不能代替其他平台。

网站、skill 收录站、脚本工具使用对应 kind 和真实访问/使用说明，不伪造 exe 或安装状态。.bat/.cmd 不能按当前 exe 白名单自动识别；要支持它们需另行设计启动权限与识别实现。

## 描述文件与命令

模板见 ../assets/launcher-adapter.example.json。`package.path`、`iconPath` 相对描述文件；`executable` 是应用主程序名，`package.path` 是安装器或 ZIP。`package.type` 为 installer/portable-zip；`installation` 在 installer 时必填。可选 `videoIds` 为真实抖音 ID、`backgroundPath` 为实际封面路径。

```powershell
# 先按项目生成发布包，计算真实哈希并填写描述文件
Get-FileHash -Algorithm SHA256 -LiteralPath '.\dist\your-app-win-x64.zip'
# 从本 skill 目录运行（或使用脚本绝对路径）
python scripts/check_adapter.py '项目路径\launcher-adapter.json'
python scripts/check_adapter.py '项目路径\launcher-adapter.json' --launcher-root 'E:\共享\创业\捞鱼软件中心' --strict
# 已安装时才添加 --installed
```

不指定启动器目录时会显示集成未验收警告。strict 将所有警告变为未完成，退出码 2；错误退出码 1；无错误和警告退出码 0。报告包含本地路径，仅作为本地验收资料保存，不上传公开目录。

## 发布验收

- 自查报告无失败和未完成项，下载记录匹配最终包，不用旧版本哈希。
- 安装版：真实安装，确认开始菜单、卸载记录、图标、用户选项；重开启动器看到“打开软件”，点开正确程序。
- 便携版：下载并通过哈希验证，正常准备；重启启动器仍关联；目录依赖完整、应用能运行。
- 原版本升级后仍被识别；应用数据保留；取消下载或失败不误显示已安装。
- 人工确认官网详情、视频和对应软件一致，平台按钮正确。
- 在产品 SKILL.md 和 docs/agent.md 中记录适配入口与验收报告。新增或修改适配协议时更新本规范版本。
